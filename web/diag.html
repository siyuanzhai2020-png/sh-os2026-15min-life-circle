4. 常见的四种原因与对策

先看第 2 节的 ⓪b 行：它决定你属于下面哪一类。

  1. 整个外网都不通，只有本站正常（⓪b 失败、⓪ 通过）：这是**浏览器 profile 的代理配置问题**， 不是网络本身的问题——因为 headless 浏览器（同一个 msedge.exe、全新 profile）能正常出网。
    1. 地址栏打开 edge://net-internals/#proxy，看 "Effective proxy settings"： 若显示 127.0.0.1:18911 之类的本地代理或某个 PAC 地址，就是它。
    2. edge://settings/system → 「打开计算机的代理设置」，关掉手动代理。
    3. 检查代理类扩展（SwitchyOmega / Proxy Switchy / Clash 配套插件）；本机注册表里就留着 ProxyServer=127.0.0.1:18911 的痕迹，代理工具没在跑时这些配置就是死路。
    4. 用无痕窗口重开本页（默认禁用扩展）；若通过，就是扩展在设代理。
    5. 修复前演示用「体检底图」模式：底图由服务端取好再发给浏览器，不依赖浏览器出网。
  2. 只有 api.map.baidu.com 不通（⓪b 通过、① 失败）：域名级拦截。 ① 无痕窗口对比；② 检查 C:\Windows\System32\drivers\etc\hosts； ③ 暂停 uBlock/AdGuard/隐私盾类插件对该站的拦截。
  3. AK 白名单/配额（脚本能下载但 BMapGL 未就绪）：到百度控制台确认 AK 类型是「浏览器端」、白名单含当前来源（http://127.0.0.1:8000 或 *）。
  4. 都不是：主界面的「体检底图」模式走服务端静态图，不依赖浏览器加载百度脚本， 一定可用——演示时用这个模式即可。
